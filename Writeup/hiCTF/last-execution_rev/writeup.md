# Last Execution — Writeup

**Категория:** Reverse / Crypto (custom VM)
**Файл:** `last-execution.zip` → `last_execution.img` (8 650 752 байт)
**Флаг:** `hiCTF{3x3c_9_r3m3mb3rs_4ll_but_th3_l4st_h4lt_l13s}`

> The final command was executed. EXE-9 never responded again. A single image survived: `last_execution.img`. It contains broken code, twisted tables, and something that was never meant to be found.

---

## TL;DR

1. Образ — «холодный дамп» виртуальной машины EXE-9: заголовок, таблица сегментов, код с ротацией страниц, таблицы с ротацией строк, зашифрованные «печати».
2. Внутри образа лежит документ (PRIMER) с описанием ISA, но **три константы в нём неверны** — их нужно подобрать по контрольным трассам из того же документа.
3. Настоящая цепочка выполнения длиннее заявленной: `MAIN → FOLD_A → FOLD_B → LIMIT → FINAL → LIMIT → FINAL`. Сегмент `EXEC_LIMIT` — цикл на ~2·10¹³ итераций, он проходится **jump-ahead'ом** по периоду LCG.
4. «Консольная запись» с регистрами — приманка: отличается от честного состояния одним битом R2 и открывает `TEST_SEAL_2` (`hiCTF{f4k3_fl4g}`). Настоящий флаг в `WILL_SEAL` открывается только честно посчитанным состоянием.

## 1. Разведка

```bash
unzip last-execution.zip
file last_execution.img        # data
strings -n 6 last_execution.img | head
```

Первые байты — `EXE9CORE`. Заголовок (big-endian):

| offset | поле |
|---|---|
| 0x00 | magic `EXE9CORE` |
| 0x08 | version `0x0901` |
| 0x0C | число сегментов N (=24) |
| 0x10 | `EXEC_SEED` = `0x9e3779b9f00dcafe` |
| 0x18 | `TABLE_SEED` = `0xbadc0ffee0ddf00d` |
| 0x20 | `ENTRY` = 1 |
| 0x30 | CRC32 заголовка |

Таблица сегментов — с `0x100`, записи по `0x40` байт: `SEG_ID, TYPE, OFFSET, SIZE, FLAGS, AUX, CRC32, NAME`.

Важные сегменты:

| id | имя | тип | комментарий |
|---|---|---|---|
| 1 | EXEC_MAIN | CODE | вход |
| 2 | EXEC_FOLD_A | CODE | |
| 3 | EXEC_FOLD_B | CODE | |
| 5 | EXEC_LIMIT | CODE | «лимит» |
| 4 | EXEC_FINAL | CODE, **writable** | самомодифицируется |
| 6 | EXEC_SELFTEST | CODE | эталон для проверки эмулятора |
| 11 | DLOOK | TBL | 256 КБ таблицы |
| 12 | DSEED | TBL | |
| 10 | PRIMER | MANUAL | документация VM |
| 20 | WILL_SEAL | SEAL | зашифрованный флаг |
| 21–24 | TEST_SEAL_1..4 | SEAL | тестовые печати |
| 30 | TELEMETRY | TRC | «консольная запись» |
| 31 | SYMBOLS | SYM | устаревшие символы (шум) |
| 40, 50–55 | ACCEPT_LEGACY, REV_NOTES, FILLER_* | | мусор / ложные заметки |

CRC всех сегментов сходятся, так что образ не повреждён.

Текст PRIMER (`0x43300`) описывает всё, что нужно:

- **Fetch:** страницы кода по 256 байт, у каждой своя ротация `ROT[p]`, слово `ROL64(raw, ROT[p])`.
- **Dispatch:** `idx = (op_byte + pc>>? + AUX) mod 256`, дальше таблица опкодов (30 штук). Неизвестный `idx` не падает, а декодируется как «правдоподобная арифметика» (fallback по `idx mod 8`) — защита от наивного линейного дизассемблера.
- **Chaining:** `HALT imm` → `next_id = imm ^ low32(R1)`; `0xFFFFFFFF` — конец.
- **Таблицы:** строки по 64 байта, у каждой своя ротация `rr[i]`, чтение через `LDRR`.
- **Печать:** `SEAL-256` (16 раундов, S-box выводится из `DLOOK`) + ротация колонок.
- **Ключ:** `SHA256("LASTEXEC" || R1..R4 || "LASTEXEC")`, где `R1..R4` — состояние на финальном `HALT`.

Сегмент `REV_NOTES` («rev 0.7 DRAFT») — заведомо неверные заметки (ROR вместо ROL, `R4` вместо `R1` и т. д.), на них полагаться нельзя. `SYMBOLS` — тоже мусор.

## 2. Эмулятор и «неправильные» константы

Реализуем VM строго по PRIMER и сверяемся с тремя встроенными контрольными точками:

| Контроль | Источник |
|---|---|
| `ROT[0..2]` для EXEC_MAIN = `0, 0x39, 0x37` | PRIMER §2.4 |
| `rr[0..3]` для DSEED = `0x31, 0x2D, 0x30, 0x16` | PRIMER §5.2b |
| SHA-256 состояния после `EXEC_SELFTEST` = `0b6d8d47…bbcf2` | PRIMER §6.3 |
| декодирование: опкод `0x93` при `pc=0x40`, `AUX=0x47` → `idx 0xE2` (LDRR) | PRIMER §3.2b |

Дословная реализация спецификации **не проходит ни одну из проверок**. Расхождения, найденные подбором по трассам:

### 2.1 Ротация строк таблицы

В тексте: `rr[i] = (rr[i-1]*17 + B + i*11) mod 64`.
Трасса DSEED `49, 45, 48, 22` ломается, а разность «нужное − получившееся» = `2, 4, 6 = 2·i`, значит константа **13**:

```
rr[i] = (rr[i-1]*17 + B + i*13) mod 64     # B = первый байт сохранённой строки i-1
```

### 2.2 Ротация страниц кода

Формулы `ROL 19` / `ROL 31` не дают `ROT = 0, 0x39, 0x37`. Перебор параметров (начальный сдвиг `a`, сдвиг шага `b`, вариант слова `w`, наличие `X`) на двух ограничениях даёт несколько кандидатов; единственный, у которого `SELFTEST` даёт нужный SHA-256, — **начальный сдвиг 17**:

```
m   = ROL64(EXEC_SEED ^ (SEG_ID*K mod 2^64), 17)
m   = ROL64(((m ^ w ^ X) * K) mod 2^64, 31)      # w = be64 в начале страницы p-1
ROT[p] = m mod 64
```

### 2.3 Диспетчеризация

В тексте `pc >> 4`, но трасса `0x93 @ 0x40, AUX=0x47 → 0xE2` сходится только с `pc >> 3` (номер инструкции):

```
idx = (op_byte + (pc >> 3) + AUX) & 0xFF
```

После этих правок `EXEC_SELFTEST` исполняется за 56 шагов и даёт

```
R1=b32aff5565d79afc R2=2028ad4561d488d8 R3=53fa2553de2ce460 R4=0b11e216ecec9b9e
sha256(R1||R2||R3||R4) == 0b6d8d4770eac443de6b9b73340a4a262117d9da42e6ced9411ebda286bbbcf2
```

Эмулятор верифицирован.

Прочие детали семантики, которые подтвердились косвенно (иначе цепочка не попадала бы в нужные сегменты):

- `Z` ставится только `CMP`, но **переживает `HALT`** (как и регистры). Поэтому пара `ANDI …; JZ …` в цикле на самом деле ветвится по «старому» `Z`, а не по результату `ANDI`.
- `JZ/JNZ/JMP imm` — `pc ← pc + 8 + sext(imm)`, `imm` в байтах.
- `STW/STB` допустимы только в сегментах с `FLAGS & 1` (здесь — только `EXEC_FINAL`), адреса абсолютные (смещения в файле).
- `LDRR`: строка из файла циклически сдвигается **вправо** на `rr[i]`, затем читается `be64` по смещению `k ≤ 56`.

## 3. Реальная цепочка выполнения

Запуск с `ENTRY=1`:

```
HALT seg1 -> seg2   (R1 low32 ^ imm = 2)
HALT seg2 -> seg3   (… = 3)
HALT seg3 -> seg5   (… = 5)   ← попадаем в EXEC_LIMIT и «зависаем»
```

Консоль утверждает `MAIN → FOLD_A → FOLD_B → FINAL`, поэтому `seg3 → seg5` выглядит как ошибка эмуляции (в `R1` расхождение в один бит относительно «ожидаемого» перехода на 4). Но дизассемблер `EXEC_LIMIT` всё объясняет — в его конце:

```
SHR  R10, R1, 32
SHL  R10, R10, 32
LI   R11, 0x1337c0da      (LUI/ORI)
OR   R1,  R10, R11        ; low32(R1) = 0x1337c0da
HALT 0x1337c0de           ; 0x1337c0de ^ 0x1337c0da = 4  → EXEC_FINAL
```

То есть `LIMIT` — **законный промежуточный сегмент**, а не ловушка: консольная цепочка его просто опускает. Настоящий маршрут:

```
MAIN → FOLD_A → FOLD_B → LIMIT → FINAL → LIMIT → FINAL (HALT → 0xFFFFFFFF)
```

`FINAL` дважды передаёт управление в `LIMIT` (с изменённым `R1`), потому второй `LIMIT` тоже нужно пройти.

## 4. EXEC_LIMIT: цикл на ~2·10¹³ итераций

Дизассемблированное тело (псевдокод):

```c
R6  = 0xe31e346c0cf0ce3a ^ R1 ^ R2;
R8  = 0x6666a6c5e864f942 ^ R2;
R9  = 0x0f0ee2c89abc + ((LDRR(0x8318) & 0xffffff) << 20);   // = 0x123456789abc
R5  = 0x1a5c;  R12 = 0;  R13 = 0x19660d;  R14 = 0x3c6ef35f;  R15 = 0;

do {
    R7  = ((R6 & 0x3ffff) * R13 + R14) & 0x3ffff;      // LCG по модулю 2^18
    R6  = (R6 ^ (R6 & 0x3ffff)) | R7;                    // высокие биты R6 не меняются
    R11 = ROL(R6, 27) ^ R6;      R8 += R11;
    R10 = (R12 << 15) | R5;      R8 += R10;
    t   = R5 + 0x4001;  R5 = t & 0x7fff;
    if (t >> 15) R12 = (R12 + 1) % 3;                    // перенос
} while (--R9 != 0);

R3 = ROL(R8, 7) ^ R6;
R1 = (R1 >> 32 << 32) | 0x1337c0da;
HALT 0x1337c0de
```

`R9 = 0x123456789abc ≈ 2·10¹³` — наивная эмуляция не закончится. Но состояние `(R6 & 0x3ffff, R5, R12)` периодично:

- LCG: `a = 0x19660d ≡ 1 (mod 4)`, `c` нечётное → период Халла–Добелла `2¹⁸ = 262 144`;
- `R5` (шаг `0x4001`, нечётный) → период `2¹⁵`;
- счётчик переносов `R12 mod 3`: за 262 144 шага набегает 131 080 ≡ 1 (mod 3) переносов → полный период = `3 · 262 144 = 786 432`.

Алгоритм jump-ahead (на входе в цикл):

1. симулируем один период `P = 786 432`, проверяем, что `(R6, R5, R12)` вернулись в исходное состояние;
2. `S = R8_после − R8_до` (приращение `R8` за период);
3. `qq = (N − 1) // P`; `R8 += qq·S`; `R9 −= qq·P`;
4. остаток (≤ P итераций) докручиваем обычной эмуляцией.

```c
u64 n=R[9], a6=R[6], a8=R[8], a5=R[5], a12=R[12];
u64 s6=a6, s5=a5, s12=a12, s8=a8;
const u64 P = 786432;
for (u64 i = 0; i < P; i++) {
    u64 r7 = ((s6 & 0x3ffff) * 0x19660dULL + 0x3c6ef35fULL) & 0x3ffff;
    s6 = (s6 ^ (s6 & 0x3ffff)) | r7;
    s8 += rol(s6, 27) ^ s6;
    s8 += (s12 << 15) | s5;
    u64 t = s5 + 0x4001; s5 = t & 0x7fff; if (t >> 15) s12 = (s12 + 1) % 3;
}
assert(s6 == a6 && s5 == a5 && s12 == a12);
u64 S = s8 - a8, qq = (n - 1) / P;
R[8] += qq * S;  R[9] -= qq * P;
```

Хук срабатывает при **каждом** входе в `EXEC_LIMIT` (их два). Всего эмуляция занимает ~2,1 млн шагов.

## 5. Финальное состояние

```
HALT seg5 -> seg4  (R1 = 422ed4a11337c0da)
HALT seg4 -> seg5  (R1 = 3e5c9f535eed0001)
HALT seg5 -> seg4  (R1 = 3e5c9f531337c0da)
HALT seg4 -> 0xFFFFFFFF   конец

R1  = 30677df2a112fffb
R2  = ff975fd2b1f15576
R3  = abec2195f731c083
R4  = 9c3fb793eed6da86
R15 = 5354414c   ('STAL' — маркер успеха ✔)
```

Сравнение с «консольной записью» (TELEMETRY, `0x463c2`):

| | консоль | эмуляция |
|---|---|---|
| R1 | `30677DF2A112FFFB` | `30677df2a112fffb` ✔ |
| R2 | `FF975FD2B1F1`**`4`**`576` | `ff975fd2b1f1`**`5`**`576` ✘ (бит 12) |
| R3 | `ABEC2195F731C083` | совпадает ✔ |
| R4 | `9C3FB793EED6DA86` | совпадает ✔ |

PRIMER §8 уверяет: «если эмуляция расходится с консолью, консоль права». Это **приманка**: консольное состояние подогнано под `TEST_SEAL_2` («acceptance rig … do not re-derive»). Проверка:

```
ключ из консольного состояния → TEST_SEAL_2 = "hiCTF{f4k3_fl4g}"
```

Заодно это подтверждает, что наш дешифратор SEAL-256 написан правильно. Для `WILL_SEAL` нужно состояние, полученное реальным исполнением.

## 6. Расшифровка WILL_SEAL

### 6.1 Ключ

```python
key = sha256(b'LASTEXEC' + b''.join(struct.pack('>Q', r) for r in (R1,R2,R3,R4)) + b'LASTEXEC').digest()
```

### 6.2 S-box

Берём логические строки 0–3 сегмента `DLOOK` (с учётом `rr[i]`, ротация вправо) → 256 байт `D`; затем

```python
perm = list(range(256))
for i in range(255, 0, -1):
    j = D[i] % (i + 1)
    perm[i], perm[j] = perm[j], perm[i]
SBOX = perm; INV_SBOX[SBOX[x]] = x
```

### 6.3 Ключевое расписание и расшифровка блока

```python
def round_keys(key):
    x = list(struct.unpack('>4Q', key)); out = []
    for i in range(1, 18):
        for j in range(4):
            t = (x[j] + x[(j+1)%4] + (K * (4*(i-1)+j+1) & M)) & M
            t ^= x[(j+3)%4] >> 7
            x[j] = rol(t, 13)
        out.append(struct.pack('>QQ', x[0]^x[2], x[1]^x[3]))
    return out                       # RK[0..16]

IP = [0,13,10,7,4,1,14,11,8,5,2,15,12,9,6,3]

def dec_block(b, RK):
    st = bytes(a ^ c for a, c in zip(b, RK[16]))
    for r in range(15, -1, -1):
        st = bytes(st[IP[t]] for t in range(16))
        st = bytes(INV_SBOX[v] for v in st)
        st = bytes(a ^ c for a, c in zip(st, RK[r]))
    return st
```

### 6.4 Формат печати

`[0..15]` — сдвиги колонок, дальше `L = (SIZE-16)/16` блоков по 16 байт. Исходное преобразование: `stored[r][c] = ct[(r − shift[c]) mod L][c]`, значит при открытии `ct[r][c] = stored[(r + shift[c]) mod L][c]`. После расшифровки всех строк — снимаем PKCS#7.

```python
un[r][c] = rows[(r + shift[c]) % L][c]
pt = b''.join(dec_block(bytes(r), RK) for r in un)
pt = pt[:-pt[-1]]
```

### 6.5 Результат

```
WILL_SEAL → hiCTF{3x3c_9_r3m3mb3rs_4ll_but_th3_l4st_h4lt_l13s}
```

Паддинг валиден, плейнтекст читаем — «по чему убедиться» (PRIMER §7.3) здесь однозначно. Остальные тестовые печати (`TEST_SEAL_1,3,4`) на этом ключе дают мусор — они предназначены для других состояний.

## 7. Ловушки образа

| Ловушка | Как обходится |
|---|---|
| Три неверные константы в PRIMER | подбор по трассам §2.4 / §5.2b / §3.2b + SHA-256 SELFTEST |
| Fallback-декодирование неизвестных `idx` | не линейный дизассемблер, а трассировка по реальному потоку выполнения |
| Самомодификация (`STW` в `EXEC_FINAL`) | fetch читает **текущую** память, ротации считаются по исходным байтам |
| Консольная цепочка без `LIMIT` | увидеть `HALT 0x1337c0de` в конце `EXEC_LIMIT` → переход на 4 |
| Цикл на ~2·10¹³ итераций | jump-ahead по периоду LCG |
| `Z` переживает `HALT`, `JZ` после `ANDI` | реализовать ровно так — иначе цепочка не попадёт в нужные сегменты |
| Телеметрия «стоит» и подделка `TEST_SEAL_2` | доверять только эмулированному состоянию |
| `REV_NOTES`, `SYMBOLS`, `FILLER_*`, `APPENDIX A/B` | шум |
