# hiCTF Sentinel Gateway — разбор (rev-obs-flow)

Nov 1, 2026 · @Demian

## TL;DR

Флаг: `hiCTF{m4th_c0ntr0l_fl0w_3ll1pt1c_dlog_4f7b2c9e}`

`challenge` — stripped ELF x86-64 (non-PIE), валидатор ключа с обфускацией потока управления (control-flow flattening). 47-байтный ключ `hiCTF{…40 символов…}` проверяется виртуальной машиной-диспетчером: 40 внутренних байт читаются как 10 little-endian `uint32` (d0..d9), и каждое состояние VM — отдельный математический гейт на свою пару dword'ов.

Использованная математика по группам: квадратичные сравнения mod 2³¹−1, эллиптическая кривая (скалярное умножение), дискретный логарифм, линейная система mod 0xfffffffb и тест простоты Миллера–Рабина.

angr «в лоб» задачу не берёт (почему — ниже). Решал структурным реверсом: разложил гейты и решил каждый теорией чисел на чистом Python, а кандидатов проверял запуском самого бинаря как оракула. Расшифровка внутренней части читается как тема задачи — *math control flow elliptic dlog*.

## Разведка

В архиве один файл `challenge`: `ELF 64-bit LSB executable, x86-64, dynamically linked, stripped`. Тип `EXEC` (не PIE) — значит адреса `0x401…` реальные, удобно для гиперссылок и брейкпоинтов.

Полезные строки: `=== [ hiCTF Sentinel Gateway ] ===`, ` Passkey:  `, `hiCTF{`, `[-] Access Denied.`, `[-] Input error.`. Важно: **строки «успеха» в бинаре нет** — сообщение об успехе восстанавливается из состояния хеша, т.е. флаг и есть правильный passkey.

Точка входа — `0x401e90`; адрес `main` берётся из стартового стаба (`mov rdi, 0x4010c0` перед `__libc_start_main`), то есть `main = 0x4010c0`. Бинарь запускается нативно — это ключевой момент: сам бинарь служит быстрым оракулом для проверки кандидатов.

```
$ file challenge
challenge: ELF 64-bit LSB executable, x86-64, ... stripped
$ printf 'hiCTF{AAAA...}\n' | ./challenge
=== [ hiCTF Sentinel Gateway ] ===
Passkey: [-] Access Denied.   # rc=1
```

## Почему angr дал `active=0 deadended=0`

Две причины — одна мелкая, одна принципиальная.

**1. Off-by-one в рамке ввода.** Валидатор делает `fgets` → `strlen` → срезает хвостовые `\n`/`\r` → `cmp rax, 0x2e`, т.е. длина ровно **47** и `}` в индексе **46**. В исходном скрипте `}` стоял в байте 45, а `\n` в 46 → после среза длина 46 → **все** пути валятся в fail-блок `0x401570`. В angr fail-адреса были в `avoid`, поэтому все состояния ушли в avoid-стек (он не попадает ни в `active`, ни в `deadended`) → ровно `active=0 deadended=0` за 1.2 с.

Кстати, `ENTRY = 0x4010C0` и `SUCCESS = 0x401E24` в скрипте были **верные** (`0x4010C0` — это `main`).

**2. Принципиальная.** Даже с исправленной рамкой наивный angr здесь почти наверняка захлебнётся. Это не линейный crackme, а **control-flow flattening** — VM-диспетчер по 32-битному состоянию, а внутри обработчиков:

- модулярное возведение в степень (square-and-multiply с символьной экспонентой);
- SipHash-подобная перестановка хеш-состояния;
- тест простоты Миллера–Рабина;
- сложение точек эллиптической кривой с модулярными инверсиями.

Символьное исполнение по modpow с символьной экспонентой и по EC-операциям (там modinv) порождает неподъёмные SMT-запросы и взрыв путей на циклах возведения в степень. Задача специально сделана против «кнопки angr»: нужен структурный реверс.

## Предвычисления: 10 dword'ов → слоты

После рамки идёт прямолинейный (без ветвлений) блок, который читает 10 внутренних dword'ов и складывает производные величины в слоты стека. VM потом проверяет эти слоты. Внутренние 40 байт = `d0..d9` (little-endian uint32), `d_k = input[6+4k : 10+4k]`.

| Слот / величина | Формула | Гейт |
| --- | --- | --- |
| m0, m1 | `d0 mod M`, `d1 mod M`, M = 2³¹−1 | F |
| \[0x38\] | `m0² mod M` | F |
| \[0x40\] | `31337·m1² mod M` | F |
| \[0x48\] | `(m0·m1 mod M) ⊕ 0x37c0f52c` | F |
| \[0x10\], \[0x18\] | `d2 mod (10⁹+7)`, `d3 mod (10⁹+7)` | D |
| \[0x70\] | `P(d2) ⊕ (d3² mod 10⁹+7)` | D |
| \[0x78\], \[0x7c\] | `d4 mod (2³¹−2)`, `d5 mod (2³¹−2)` | G |
| \[0x60\] | `d6,d7` через mod 0xfffffffb | E |
| \[0x30\] | `d8,d9` через sum/prod mod M | A |

Здесь `P(d2) = d2³ + 133742·d2 + 0x30730db7 (mod 10⁹+7)` — это уже уравнение эллиптической кривой. Каждый обработчик берёт свой слот и требует «индекс 0» в таблице переходов — это и есть равенство-гейт.

## Гейт d0, d1 — квадратичная система (handler F)

Обработчик F требует `[0x48] == 0` и `[0x38] − [0x40] == 0x1e054920`. В переводе на m0 = d0 mod M, m1 = d1 mod M (M = 2³¹−1):

```latex
\begin{aligned}
m_0 \cdot m_1 &\equiv \mathtt{0x37c0f52c} \pmod{M}\\
m_0^2 - 31337\,m_1^2 &\equiv \mathtt{0x1e054920} \pmod{M}
\end{aligned}
```

Из первого уравнения `m0 = C₂·m1⁻¹`. Подстановка во второе даёт квадратное относительно `t = m1²`:

```latex
31337\,t^2 + \mathtt{0x1e054920}\,t - \mathtt{0x37c0f52c}^2 \equiv 0 \pmod{M}
```

Решаем квадратное через дискриминант и корень по Тонелли–Шенксу (M простое), затем `m1 = √t`, `m0 = C₂·m1⁻¹`. Из m0, m1 восстанавливаем `d_i ∈ {m_i, m_i + M}` и фильтруем по печатным ASCII. Остаётся единственный вариант:

**d0 = `m4th`, d1 = `_c0n`.**

## Гейт d2, d3 — эллиптическая кривая (handler D)

Самая коварная группа. Хелпер `0x402220` оказался **сложением точек эллиптической кривой** над F\_p с флагом «точка на бесконечности» (формулы сложения/удвоения используют только `a`, есть modinv для углового коэффициента).

```latex
y^2 = x^3 + 133742\,x + \mathtt{0x30730db7} \pmod{10^9+7}
```

⚠️ **Ловушка:** в удвоении коэффициент `a = 0x20a6e = 133742`, а не 133230 — легко ошибиться при чтении hex. С неверным `a` точки не ложатся на кривую, и всё рассыпается. Это же `133742` стоит в линейном члене `P(d2)` (слот 0x70) — seed обязан лежать на той же кривой.

Handler D — это double-and-add: аккумулятор стартует с `seed = (d2 mod p, d3 mod p)`, база — константная точка `G' = (123456789, 239241263)`, экспонента 1337. Гейт: `[0x70] == 0` (seed на кривой) и результат == `Q = (0x2d0c1bbd, 0x205c7191)`.

```latex
\text{result} = \text{seed} + [1337]\,G' = Q \;\Rightarrow\; \text{seed} = Q - [1337]\,G'
```

Точную структуру снял **динамически** — брейкпоинтом на входе `0x402220` в gdb прологировал все пары точек-слагаемых (база G' удваивается, аккумулятор += база). Так как формулы EC алгебраичны, моя Python-реализация совпала с бинарём байт-в-байт на всех замерах.

Инверсия: `seed = Q − [1337]G' = (815114349, 812410463)` → **d2 = `tr0l`, d3 = `_fl0`.**

## Гейт d4, d5 — дискретный логарифм (handler G)

Обработчик G считает два модулярных возведения в степень (square-and-multiply с Barrett-редукцией по `p = 2³¹−1`), где показатели — `d4 mod (p−1)` и `d5 mod (p−1)`. Для принятия нужно:

```latex
7^{\,d_4} \equiv \mathtt{0x7bb949ec}, \qquad 11^{\,d_5} \equiv \mathtt{0x0b3bbfc8} \pmod{2^{31}-1}
```

Это дискретный логарифм. Порядок группы `p−1 = 2·3²·7·11·31·151·331` — гладкий, поэтому работает **Полиг–Хеллман** (в каждой подгруппе — baby-step/giant-step), потом CRT. Получаем `d4 ≡ e4`, `d5 ≡ e5 (mod p−1)`; печатный фильтр выбирает единственный дворд из `{e, e + (p−1)}`.

**d4 = `w_3l`, d5 = `l1pt`.**

## Гейты d6,d7 и d8,d9; финал handler C

**d6, d7 — линейная система (handler E).** `[0x60] == 0` даёт два линейных сравнения mod `M2 = 0xfffffffb`:

```latex
\begin{aligned}
\mathtt{0xcc1321}\,d_6 + \mathtt{0x3ade68b1}\,d_7 &\equiv \mathtt{0x92660155}\\
\mathtt{0x75bcd15}\,d_6 + \mathtt{0x211ecd59}\,d_7 &\equiv \mathtt{0x7da7aac3}
\end{aligned} \pmod{M_2}
```

Обратная матрица 2×2 mod M2 → **d6 = `1c_d`, d7 = `log_`.**

**d8, d9 — сумма/произведение + простота (handler A).** `[0x30] == 0`: `(d8+d9) ≡ 0x4770c967`, `(d8·d9) ≡ 0x2e97d196 (mod M)`. Это корни квадратного `x² − Sx + P ≡ 0 (mod M)`. Кроме того, обработчик требует, чтобы `isPrime(d8 ⊕ 9)` и `isPrime(d9 ⊕ 0x11)` (тест Миллера–Рабина с простыми-свидетелями на `0x403080`) — это снимает неоднозначность порядка корней. → **d8 = `4f7b`, d9 = `2c9e`.**

**Handler C — финал.** Генерирует 98 байт из хеш-состояния XOR keystream (`0x4031a0`), проверяет полиномиальный хеш `== 0xb4f079c8` и печатает результат (`printf("%s")`). Хеш (SipHash-подобный) односторонний, но входы уже жёстко зафиксированы алгебраическими гейтами, поэтому хеш сходится «автоматически» — инвертировать SipHash не нужно.

(Обработчик B — чистая обфускация: `3^(p−1) mod p = 1` всегда, т.е. безусловный переход к F.)
