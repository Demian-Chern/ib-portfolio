# Райтап: Apex Multi-Threaded Settlement Engine (pwn)

Nov 1, 2026 · @Demian

## TL;DR

**Категория:** pwn — состояние гонки в многопоточном коде.

**Флаг:** `CTF{t0ct0u_mult1thr34d_r4c3_c0nd1t10n_w1n_8d3f_dc1473999a}`

Бинарник даёт две «гарантии»: средства нельзя потратить дважды и секретные записи недоступны без root-доступа. Обе ложны из-за одной ошибки — **TOCTOU** (time-of-check → time-of-use): проверка и использование разнесены во времени, а между ними стоит `usleep(25 мс)`. Это окно и есть вся задача.

1. **Двойное списание.** Воркер эскроу проверяет `баланс ≥ сумма`, спит 25 мс, потом списывает. Несколько параллельных переводов успевают пройти проверку по одному и тому же балансу; списания затем уводят беззнаковый баланс в переполнение (≈ 1.8·10¹⁹) — хватает на VIP-тариф (10 000), который открывает анклав.
2. **Обход проверки пути.** Стример анклава делает `strstr(path, "flag")`, спит 25 мс, потом `fopen(path)`. Стримим безобидный путь (проверка пройдена), а внутри окна подменяем путь слота на `/flag` — воркер открывает флаг.

## Разведка

Один файл `challenge` — 64-битный ELF, PIE, динамически слинкован, **stripped**. Полный набор защит (PIE, Full RELRO, NX, stack canary) — классическое переполнение не вариант, баг логический.

Главные намёки дают импорты и строки: `pthread_create` / `pthread_detach` / `usleep` (потоки плюс искусственные задержки), `fopen` / `fread` / `strstr`, а также `/flag`, `./flag.txt`, `/tmp/preview.txt`, «Root Admin clearance required», «VIP Tier».

Главное меню:

```
1. View Account & Holdings
2. Initiate Escrow Transfer
3. Withdraw from Escrow Vault
4. Upgrade Account Tier (VIP: 10,000 credits)
5. Access Secure Vault Enclave   <- подменю Create/Stream/Edit, требует VIP
6. Exit
```

Глобальное состояние (.bss, смещения от базы образа):

| Смещение | Назначение | Старт |
| --- | --- | --- |
| 0x43e0 | баланс (u64) | 100 |
| 0x43e8 | эскроу-хранилище (u64) | 0 |
| 0x43f0 | флаг VIP (u32) | 0 |
| 0x43f4 | root-доступ анклава (u32) | 0 — **нигде не ставится** |
| 0x4060 | 4 слота документов × 176 Б | — |
| 0x4320 | 8 ордеров эскроу × 24 Б | — |

Структуры. **Слот** (176 Б): `+0x00` статус, `+0x24` буфер пути (его читают и `strstr`, и `fopen` — здесь гонка), `+0xa8` pthread\_t. **Ордер** (24 Б): `+0x00` id, `+0x04` статус (1→2→3/4), `+0x08` сумма (u64), `+0x10` pthread\_t.

На старте стоит `alarm(60)` — сессия живёт 60 секунд, потом «Session timed out». Этого с запасом хватает.

## Уязвимость 1 — двойное списание (гонка на балансе)

«Initiate Escrow Transfer» (пункт 2) берёт сумму, проверяет баланс и запускает на каждый ордер фоновый поток-воркер. Воркер (псевдокод):

```
settle_worker(order):
    if order.status != PENDING: return
    if balance < order.amount:          # ПРОВЕРКА (time-of-check)
        order.status = CANCELLED; return
    order.status = PROCESSING
    usleep(25000)                        # <-- окно 25 мс
    balance -= order.amount              # ИСПОЛЬЗОВАНИЕ (time-of-use)
    order.status = COMPLETED
    vault   += order.amount
```

Проверка `balance < amount` и само списание `balance -= amount` разделены сном в 25 мс и ничем не синхронизированы (мьютекса нет). Главный поток при подаче ордера тоже проверяет баланс, но списывает его не он, а воркер — с задержкой.

**Эксплуатация.** Баланс = 100. Быстро, пока ни один воркер не проснулся, подаём 6 переводов по 100:

- каждый воркер читает `balance = 100`, условие `100 ≥ 100` выполнено → все 6 уходят в сон;
- через 25 мс они просыпаются и по очереди делают `balance -= 100`.

Баланс — **беззнаковый** (`unsigned long long`, печатается как `%llu`). После `100 - 600` он уходит в переполнение ≈ 1.8·10¹⁹. Хватило бы и двух параллельных переводов: первый обнуляет, второй уже уводит в underflow.

Апгрейд VIP (пункт 4) требует `balance ≥ 10000`, списывает 10000 и ставит `VIP = 1`. С переполненным балансом проходит мгновенно → открывается анклав.

## Уязвимость 2 — обход проверки пути (гонка в стримере)

В анклаве (пункт 5, нужен VIP) три действия: создать слот, стримить файл, править путь слота. Стример запускает поток-воркер (псевдокод):

```
stream_worker(slot):
    if strstr(slot.path, "flag"):        # ПРОВЕРКА: путь содержит "flag"?
        if enclave_root_flag == 0:        # 0x43f4 — всегда 0
            print("SECURITY ALERT: ... denied"); return
    usleep(25000)                         # <-- окно 25 мс
    f = fopen(slot.path, "r")             # ИСПОЛЬЗОВАНИЕ: тот же буфер slot.path
    dump(f)
```

Два изъяна:

1. **«Защита» — это просто `strstr(path, "flag")`.** Флаг root-доступа (`0x43f4`) в коде **никогда не выставляется**, так что честно её не пройти: любой путь к флагу (`/flag`, `./flag.txt`) содержит подстроку `flag` → отказ.
2. **TOCTOU.** `strstr` (проверка) и `fopen` (использование) читают **один и тот же буфер** `slot+0x24`, но между ними — `usleep(25 мс)`. А пункт «Edit Document Target Path» меняет этот буфер из главного потока.

**Эксплуатация:**

1. Создаём слот 0 — путь по умолчанию `/tmp/preview.txt` (без «flag»).
2. Стримим слот 0: воркер делает `strstr("/tmp/preview.txt", "flag") = NULL` → проверка пройдена → сон 25 мс.
3. Пока он спит, через «Edit» меняем путь слота 0 на `/flag`.
4. Воркер просыпается и `fopen("/flag")` → дамп флага.

Контроль: если выставить путь `/flag` **до** стрима (без гонки), получаем `SECURITY ALERT: Access denied`. Значит, обход держится именно на окне между проверкой и использованием.

## Эксплуатация: полная цепочка

Обе гонки держатся на одном окне в 25 мс. Главный поток обрабатывает ввод за микросекунды, поэтому успеваем вклиниться между проверкой и использованием.

1. **Двойное списание** — 6 переводов по 100 подряд, пауза \~0.2 с (воркеры просыпаются, баланс уходит в underflow).
2. **VIP** — пункт 4 (баланс огромен → апгрейд проходит, анклав открыт).
3. **Анклав** — пункт 5.
4. **Слот** — создать слот 0 (путь по умолчанию `/tmp/preview.txt`).
5. **Гонка** — стримить слот 0, затем сразу сменить его путь на `/flag` (правка попадает в окно 25 мс).
6. Воркер открывает `/flag` → флаг в выводе.

Ручной сценарий (что вводить в меню):

```
2 ⏎ 100 ⏎      (повторить 6 раз подряд, быстро)
   ... подождать ~0.2 с ...
4 ⏎            (Upgrade -> VIP)
5 ⏎            (Access Secure Vault Enclave)
1 ⏎ 0 ⏎        (Create Document Slot 0)
2 ⏎ 0 ⏎        (Stream Slot 0 — воркер прошёл strstr, спит 25 мс)
3 ⏎ 0 ⏎ /flag ⏎   (Edit path -> /flag, попадает в окно)
   ... через ~25 мс воркер печатает флаг ...
```

Тайминги, которые важны:

- Между 6 переводами паузы почти нет — все должны стартовать в пределах 25 мс, пока никто не списал.
- Перед апгрейдом нужна пауза ≥ 25 мс: иначе воркеры ещё не ушли в underflow и баланс = 100 → «requires 10,000».
- Между Stream и Edit — минимальная задержка (несколько мс), чтобы воркер успел сделать `strstr` раньше, чем мы перепишем путь; остаток окна уходит на `fopen` уже с `/flag`.

Если флаг лежит в `./flag.txt`, а не `/flag`, — тот же приём с путём `./flag.txt` (он тоже содержит «flag», так что только через гонку).
