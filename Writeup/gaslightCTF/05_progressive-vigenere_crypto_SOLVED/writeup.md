# gaslightCTF — progressive vigenère (crypto)

## Категория
Crypto / Classic cipher cryptanalysis

## Дано
Два файла:

```
encrypt.py                       # скрипт шифрования
output.txt                       # шифротекст (единственная строка, 547 символов)
```

`encrypt.py`:

```python
from string import ascii_lowercase

def encrypt(pt: str, keyword: str) -> str:
    m = len(keyword)
    pt = list(map(lambda x: ascii_lowercase.index(x), pt))
    key = list(map(lambda x: ascii_lowercase.index(x), keyword))

    ct = ""
    for i in range(len(pt)):
        index = (pt[i] + key[i % m] + (i // m)) % 26
        char = ascii_lowercase[index]
        ct += char

    return ct

with open('gaslight-where-the-dream-starts-3/plaintext_and_keyword.txt', 'r') as file:
    ct = file.readline().strip()
    keyword = file.readline().strip()

print(encrypt(ct, keyword))
```

Ни исходного текста, ни ключевого слова у нас нет — только сгенерированный
`output.txt` и алгоритм, по которому он получен. Задача — восстановить
открытый текст (а внутри него — флаг), не зная ни `keyword`, ни `pt`.

## Анализ алгоритма шифрования

Формула шифрования для символа на позиции `i`:

```
ct[i] = (pt[i] + key[i % m] + (i // m)) mod 26
```

где `m = len(keyword)`. Если убрать последнее слагаемое `(i // m)`, это в
точности классический **шифр Виженера**: открытый текст складывается по
модулю 26 с повторяющимся ключевым словом длины `m`.

Слагаемое `i // m` — это номер "блока", то есть сколько раз ключевое слово
уже целиком "прокрутилось" к моменту обработки символа `i`. Оно **одинаково
для всех символов внутри одного блока** длины `m` и увеличивается на 1 при
переходе к следующему блоку. Фактически это делает эффективный ключ не
статичным, а линейно "уезжающим" вперёд с каждым новым проходом ключевого
слова — разновидность **прогрессивного (progressive/drifting-key) шифра
Виженера**, комбинация классического Виженера с идеей шифра Тритемия
(Trithemius progressive cipher), где к сдвигу добавляется позиция.

Ключевое наблюдение: этот дополнительный сдвиг зависит **только от `i` и
`m`**, но не от самого ключа и не от открытого текста. А значит, если мы
переберём кандидатов на `m`, мы можем **заранее вычесть** этот сдвиг из
шифротекста и свести задачу к обычному Виженеру:

```
ct'[i] = (ct[i] - i // m) mod 26  =>  ct'[i] = (pt[i] + key[i % m]) mod 26
```

Как только текст "выпрямлен" в `ct'`, дальше работает стандартный арсенал
атак на Виженера.

## Метод взлома

1. **Перебор длины ключа `m`.** Так как длина ключевого слова заранее
   неизвестна, перебираем `m` в разумном диапазоне (взяли `1..20` — этого
   с большим запасом хватает для естественных английских слов-ключей).

2. **Снятие прогрессивного сдвига.** Для каждого кандидата `m` строим
   `ct' = unshift_progressive(ct, m)` по формуле выше.

3. **Частотный криптоанализ обычного Виженера.** Для `ct'` при данном `m`
   разбиваем текст на `m` "колонок" (символы на позициях `i % m == r` для
   каждого `r`). Внутри одной колонки все символы зашифрованы одним и тем
   же сдвигом Цезаря `key[r]`, поэтому для каждой колонки перебираем все 26
   сдвигов и через **chi-squared** статистику сравниваем распределение букв
   после расшифровки с эталонным распределением частот английского языка.
   Сдвиг с минимальным χ² — это и есть `key[r]`.

4. **Оценка кандидата по `m` в целом.** Полностью расшифровав текст для
   данного `m` собранным по колонкам ключом, считаем суммарный χ² уже для
   всего текста. Правильная длина ключа выдаёт результат, который на
   порядок (в разы) ниже, чем у всех "случайных" вариантов — это надёжный
   и однозначный сигнал.

## Реализация

```python
import string

alphabet = string.ascii_lowercase

with open('output.txt') as f:
    ct = f.readline().strip()

# эталонные частоты английских букв, %
freq = {
 'a':8.167,'b':1.492,'c':2.782,'d':4.253,'e':12.702,'f':2.228,'g':2.015,
 'h':6.094,'i':6.966,'j':0.153,'k':0.772,'l':4.025,'m':2.406,'n':6.749,
 'o':7.507,'p':1.929,'q':0.095,'r':5.987,'s':6.327,'t':9.056,'u':2.758,
 'v':0.978,'w':2.360,'x':0.150,'y':1.974,'z':0.074
}

def chi_squared(text):
    n = len(text)
    counts = {c: 0 for c in alphabet}
    for c in text:
        counts[c] += 1
    return sum(
        (counts[c] - freq[c] / 100 * n) ** 2 / (freq[c] / 100 * n)
        for c in alphabet
    )

def unshift_progressive(ct, m):
    # убираем слагаемое i // m, сводя шифр к обычному Виженеру
    return ''.join(
        alphabet[(alphabet.index(ch) - (i // m)) % 26]
        for i, ch in enumerate(ct)
    )

def crack_vigenere(ct2, m):
    key = ''
    for col in range(m):
        col_text = ct2[col::m]
        best_shift = min(
            range(26),
            key=lambda s: chi_squared(
                ''.join(alphabet[(alphabet.index(c) - s) % 26] for c in col_text)
            )
        )
        key += alphabet[best_shift]
    return key

best = None
for m in range(1, 21):
    ct2 = unshift_progressive(ct, m)
    key = crack_vigenere(ct2, m)
    pt = ''.join(
        alphabet[(alphabet.index(ct2[i]) - alphabet.index(key[i % m])) % 26]
        for i in range(len(ct2))
    )
    score = chi_squared(pt)
    if best is None or score < best[0]:
        best = (score, m, key, pt)

score, m, key, pt = best
print(f"m={m}  key={key!r}  score={score:.1f}")
print(pt)
```

## Результат

Перебор однозначно выделяет один вариант с резким отрывом по χ² от всех
остальных (46.9 против 265+ у ближайшего конкурента):

```
m = 5
key = "dream"
```

Расшифрованный текст оказался связным английским отрывком — это
адаптированная цитата из «Машины времени» Герберта Уэллса (сцена с атомами
и змеёй, кусающей свой хвост), с дописанной в конец фразой-подсказкой:

```
...as if by a flash of lightning i awoke
the flag is the indecipherable cipher
```

Фраза "the indecipherable cipher" — это историческое английское название
шифра Виженера (от французского "le chiffre indéchiffrable", "неразгаданный
шифр"), которым он был известен на протяжении трёх веков, пока Касиски и
Фридман не разработали методы его взлома. Подсказка прямо указывает на
природу самого задания.

Так как исходный алфавит шифра `ascii_lowercase` не содержит пробелов,
подчёркиваний, цифр и фигурных скобок, разбиение на слова и итоговое
оформление флага (регистр, разделители между словами, префикс) шифром не
передаются — они восстанавливаются по формату флагов конкретно этого CTF
(`gaslightCTF{...}`) отдельно от криптографической части решения.

## Официальное решение (для сверки)

В официальных материалах задачи другой, но эквивалентный по сути подход —
не χ²-перебор, а классический **тест Фридмана** (по индексу совпадений,
Index of Coincidence) для определения длины ключа `m`, и затем подбор
каждой буквы ключа через "combined IC" против эталонных частот английского
языка. Оба метода (наш χ²-перебор и официальный IC-тест) независимо
приходят к одному и тому же результату:

```
m = 5
key = "dream"
```

Официальный скрипт лежит рядом как `official_solution.py` — удобен как
альтернативная/проверочная реализация той же атаки.

## Полный скрипт

Рабочий скрипт, которым решали мы, — `crack_progressive_vigenere.py`
(см. выше весь код инлайном в разделе "Реализация") — принимает путь к
файлу с шифротекстом, перебирает `m` от 1 до 20 и печатает top-5
кандидатов по убыванию правдоподобности (по возрастанию χ²), чтобы можно
было визуально убедиться в однозначности победителя, а не слепо доверять
первому результату.

## Выводы / чеклист для похожих заданий

1. Если формула шифрования — это "Виженер + что-то ещё" (доп. слагаемое,
   зависящее от позиции/блока/счётчика), почти всегда это "что-то ещё"
   можно **аналитически вычесть заранее**, сведя задачу обратно к
   классическому Виженеру, для которого есть готовый арсенал атак.
2. Длина ключа неизвестна — не проблема: перебираем `m` в разумном
   диапазоне (для человеческих ключевых слов обычно достаточно `1..20`) и
   для каждого варианта прогоняем полноценную колонковую атаку.
3. **Chi-squared по эталонным частотам букв языка** — простой и надёжный
   критерий для одновременного решения двух задач: подбора сдвига внутри
   колонки и выбора правильной длины ключа среди кандидатов. Правильный
   вариант обычно выделяется с большим отрывом (в разы меньший χ²), что
   исключает случайное совпадение.
4. Даже без знания открытого текста заранее автоматический перебор находит
   осмысленный английский текст — значит, специальный known-plaintext (как
   в challenge с LFSR выше) для классических шифров подстановки часто и не
   нужен: репрезентативной статистики самого языка достаточно.
5. Формат флага (регистр, разделители, скобки) в подобных заданиях иногда
   не восстанавливается однозначно из расшифрованного текста, если алфавит
   шифра ограничен (например, только строчные буквы) — тогда финальную
   обёртку `CTF{...}` нужно сверять по правилам конкретного соревнования,
   а не выводить чисто механически из результата дешифровки.
